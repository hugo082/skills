# Domain-Driven Design (DDD) — Skill Boundaries

This skill defines how to use Domain-Driven Design as a thinking and collaboration framework.

## Scope

- **Cross-language:**  
  This skill is language-agnostic and applies across programming languages, stacks, and architectures.

- **Principles over implementation:**  
  It provides core DDD knowledge (concepts, vocabulary, framing), not code-level tactics or implementation patterns.

- **Non-opinionated:**  
  It does not enforce a specific DDD school, architecture style, or tooling choice.

- **Brainstorming support:**  
  It helps the agent and user explore a domain together through a DDD-inspired session lifecycle.

## DDD session lifecycle (for collaboration)

1. Frame the problem and desired outcomes  
2. Explore domain language and key concepts  
3. Identify boundaries (contexts, actors, responsibilities)  
4. Surface domain events, rules, and constraints  
5. Consolidate insights into shared understanding and next steps
