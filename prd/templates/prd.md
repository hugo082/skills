# <Feature name> — PRD
 
## Problem
[What is broken or missing in the user's world today. Not the feature — the pain.]
 
## Outcome
[The change in the user's world when this ships. One paragraph. If you can't
state it without describing the feature, the problem isn't understood yet.]
 
## Actors & scenarios
[Who is involved and what they are trying to do.]

**<actor name>** · <concrete scenarios, not personas>

## Acceptance criteria
[Numbered list. Each criterion is externally observable behavior.
Each one must be testable as a black box — no knowledge of the
implementation required to verify it.]

#### <group>

**AC-<N>** When <actor> does <action>, <observable result> within <bound>.
 
## Non-goals
[Explicit list of adjacent things this feature will NOT do. This is the
highest-leverage section: it is what prevents scope invention in later stages.
Be aggressive here.]
 
## Constraints
[Regulatory, performance, compatibility, budget — facts the solution must
respect, phrased without prescribing the solution.]
 
## Assumptions
[Everything you assumed instead of asking, or asked and the user waved through.]
 
## Open questions
[Ambiguities that remain. It is acceptable — often correct — to finish stage 1
with open questions, as long as they don't block the acceptance criteria.]
 
## Follow-ups
[Outcomes this PRD names and does not deliver, so they are not lost. One bullet each,
in user vocabulary. A non-goal is permanent and stays in Non-goals; a follow-up is
postponed. When this PRD closes, each bullet becomes a `followup` issue.]
